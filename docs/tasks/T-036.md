## Context
Mapped 2026-10-25 (project doc "תקשורת ספק־נגר: מצב קיים והמלצות"). Every email was sent once,
inline, with no retry and no record; a supplier without an email or a carpenter without a verified
email got nothing; nothing reminded anyone about an unconfirmed order; the bell counted only
message threads. On production no thread, message or "שאלה לספק" had ever been sent.

Owner's decisions 2026-10-25: one notification layer, real email delivery, in-site chat, backup
ladder and operator transparency approved. WhatsApp only as a click-to-chat button to the
supplier's number (wa.me), no Business API and no Meta registration. Every quote answer and order
confirmation must show under the bell. A clear notice on both sides when an email did not arrive.

## Done when
1. One notification layer + full bell: `notifications` + `email_outbox`, every event writes both,
   retries, bell for carpenter and supplier counts everything.
2. Delivery status from Resend webhooks; the sender sees "the email did not arrive", the owner of a
   bouncing address sees a banner; verified supplier email.
3. "שאלה לספק" and the chat reachable and tested end to end; a quote request is a thread.
4. One WhatsApp/call button component and phone normalisation.
5. Reminders and the backup ladder.
6. Operator communication-health screen.
7. Remaining small gaps (see the plan doc).

Step 3 (same branch): migration `20261025140000_message_threads_quotes`. A quote request opens its
own thread (`message_threads.quote_request_id`), linked from both quote lists. The site writes
system lines into the order or quote thread (confirmed, shipped, rejected with the note, received,
quote answered or declined); they do not move `last_sender`, so a thread never looks unanswered.
`post_message()` saves the message and updates the thread in one transaction, and `client_id`
makes a retried send return the first row instead of a duplicate. The thread view keeps an unsent
draft in the browser, retries with the same id, refreshes on focus or when the connection returns,
and shows sent/read. "שאלה לספק" on the product page is a visible button, also when signed out.
Applied to staging 2026-10-25 (checked: a repeated client_id returns the same row; a system line
leaves `last_sender`). Production waits for the owner's yes; until then `append` falls back to the
old two-step write and system lines are skipped.

Step 4 (same branch): `src/lib/phone.ts` (+ test) is the one place a number becomes a label, a
`tel:` link or a wa.me link; the four separate WhatsApp helpers (home, order page, supplier tabs,
supplier-question email, המציאון) now use it. WhatsApp is click-to-chat only and only for a mobile
number; a landline gets a call button alone. `components/app/ContactLink.tsx` is the carpenter's
WhatsApp/call button on the order page, with a prepared message carrying the order number and the
supplier's orders link (`supplierOrderMessage`). A press is reported to
`/api/app/orders/[id]/contact` (migration `20261025150000_contact_clicks`) and leaves one line an
hour in the order's conversation. Sign-up and profile phones must be real Israeli numbers
(`validPhoneKey`, same nine-digit key as before for local-format entries); a supplier's number is
stored formatted. Applied to staging 2026-10-25; production waits for the owner's yes.

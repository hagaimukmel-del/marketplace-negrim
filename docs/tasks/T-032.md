## Context
Signing in on a new device now mails a six-digit code (typed on the same page) next to the
link, and `/join` can offer "כניסה עם גוגל". The code needs table `login_codes`
(migration `20261020130000_login_codes`). Until it is applied, the code cannot be stored and
the email goes out with the link alone (`loginCodeForEmail`), while the page still asks for a
code. So the migration should reach production before, or with, the code.

Google stays hidden until `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` are set.

## Done when
- The migration is applied to staging, checked, then to production (nagarim-migrations), and
  `npm run db:types` is run.
- For Google: an OAuth client (type "Web application") in Google Cloud with
  `https://nagarimb2b.com/carpenter/google/callback` (and the staging host's) as authorised
  redirect URIs, consent screen published, and the two variables set in Vercel.

## Context
Announced publicly as coming ("בהמשך הזמנה קולית בפחות מדקה"). The chat has a mic button (browser Web Speech API, `ChatContainer.tsx`): free, fair Hebrew on Android Chrome, weak on iPhone. The old Web Speech API input from the removed legacy `/order` page is in git history (`src/app/(app)/order/search-input.tsx`, removed 2026-10-05) and didn't work on iOS Safari.

## Done when
A carpenter speaks a request in the chat (phone, Hebrew) and gets from speech to a sent purchase order in under 60 seconds, measured on staging with the smoke-test skill. It works on iOS Safari and Android Chrome.

## Notes
Decide between browser speech recognition and server transcription (cost, Hebrew accuracy, iOS). Depends on T-003 to understand quantities. Fold T-018 into this.

## Plan (owner, 2026-10-07: saved for later, not now)
1. First let the Claude agent (PR #12) go live. With it, speech from the mic button already reaches a
   model that understands free Hebrew, quantities included, so T-003 may be mostly covered by it.
2. Watch how carpenters use the browser mic for a while (`agent.llm` log lines, owner feedback).
3. If recognition is the weak point, add server transcription: record in the browser, send audio to a
   Hebrew speech-to-text service, put the text into the chat. Needs a provider choice and `STT_API_KEY`
   (the owner's to supply). Claude does not take audio input, so this is a separate service.
4. Measure speech to sent order on staging, aiming under 60 seconds. The carpenter still sends the order
   with one click; the agent only prepares it.

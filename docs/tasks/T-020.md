## Context
`src/app/api/admin/supplier-documents/upload/route.ts` uploads the file, then calls
`supabase.auth.getUser()` on the service-role client to fill `uploaded_by`. That client has no
user session, so the call returns an error and the route answers 500 after removing nothing
(the file stays in the `supplier-documents` bucket). It also inserts a row into
`admin_login_attempts` on every upload, which skews the login throttle. Found reading the code
on 2026-10-04; not reproduced on staging.

## Done when
An admin upload on staging returns 201 and creates a `supplier_documents` row, with
`uploaded_by` left null (admins have no `auth.users` row) and no `admin_login_attempts` insert.
